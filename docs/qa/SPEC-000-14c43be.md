## Achados

### BUG-QA-001 — Compose falha em checkout limpo antes da instalação das dependências

- **Gravidade:** MÉDIA (reprodutível; bloqueia o procedimento documentado de QA/local)
- **Fonte/critério:** `docs/qa/SPEC-000-handoff.md`, seção de pré-requisitos/comandos; `compose.yaml` (bind de `vendor/laravel/sail/database/mysql/create-testing-database.sh`)
- **Precondições:** clone limpo do SHA, `.env` copiado, `vendor/` ainda inexistente
- **Passos mínimos:** `cp .env.example .env`; `docker compose -p ceara_qa_spec000 up -d --build`
- **Esperado:** Compose subir e iniciar o MySQL isolado conforme o handoff
- **Observado:** o caminho de origem inexistente é criado como diretório pelo bind mount; o MySQL encerra com código 126 e mensagem sanitizada equivalente a “`...create-testing-database.sh: Is a directory`”. O handoff não instrui `composer install` antes do Compose.
- **Impacto:** um QA seguindo literalmente a preparação não consegue iniciar o ambiente nem executar os critérios; a criação automática do banco de teste também não ocorre.
- **Correção sugerida:** instalar dependências antes do Compose e validar que o script existe como arquivo executável; alternativamente, remover o bind dependente de `vendor/` e criar o banco de teste por configuração explícita/imagem própria.
- **Regressão sugerida:** teste de instalação em diretório vazio que executa exatamente a sequência do handoff e verifica `docker compose config`, subida saudável do MySQL e existência do banco de teste.

### Observação de revisão estática — fonte remota no build

`vite.config.js` baixa `Instrument Sans` de `fonts.bunny.net` durante `npm run build`. O build falhou no sandbox sem DNS e passou após rede autorizada. Isso não foi classificado como bug funcional neste parecer, mas reduz reprodutibilidade offline e deve ser considerado no contrato de build/CI (ou substituído por fonte versionada/local).
